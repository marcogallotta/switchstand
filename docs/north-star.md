# North Star

This is a guiding reference, not an execution owner. It states durable direction; it does not
assign, schedule, or enforce any current task, and nothing here grants implementation, review, or
effect authority by itself.

Durable owner: Asana task 1218288326009035. Status: strategic candidate, reviewed; Marco's formal
approval is still pending as of the last record.

## North star

Switchstand becomes a durable agentic engineering organization where replaceable model sessions take
bounded work, coordinate through external durable work/evidence state, act only through mechanically
enforced authority/effect boundaries, and learn from observed failures — without making Marco the
routine scheduler, courier, permission confirmer, poller, recovery technician, or forensic monitor.

Marco's attention should rise toward product intent, architecture/design, consequential review,
difficult debugging, and selected code review. Routine dispatch, internal sequencing, state
reconciliation, Git/release mechanics, and ordinary recovery become system responsibilities.

## Engineering order

Security/Safety > Correctness/Authority > Stability/Recovery > Operator usability/control/human-time
efficiency > Performance/throughput. Simplicity, maintainability, and debuggability constrain every
mechanism.

## Durable strategic capabilities

1. **Failure containment + recovery** — detect and prevent mechanically knowable failures where
   proportional; preserve a truthful UNKNOWN; bound blast radius; recover without transcript
   archaeology; turn important incidents into checks only when useful.
2. **External truth / authority / evidence** — work identity, authority, accepted results,
   protected-effect truth, evidence freshness, and recovery facts survive sessions. Agents,
   messages, and tool availability never create authority; consequential effects need authoritative
   readback.
3. **Autonomy by reversible exposure** — durable work, not agent count, is the scaling unit. Widen
   autonomy only when outcome/recovery evidence earns it; contract or pause on escapes or unknown
   observability. Claims never grant effect authority by themselves.
4. **Selective whole-system observability + assurance** — diagnose the model, context, harness,
   tools, host, work substrate, tests/reviewers/safeguards, and external effects. Instrument only
   evidence material to the active decision or autonomy envelope; missing relevant coverage is
   UNKNOWN. Optimize accepted useful work per Marco attention, not activity volume.
5. **Layered context + task-shape-aware coordination** — use targeted progressive context. A
   replaceable lead may synthesize or coordinate but is never the authority root. Use single-agent,
   lead+children, or specialist parallelism according to actual decomposability; do not imitate a
   human org chart by default.
6. **Replaceable harness / clients** — keep stable seams between the model/client, execution host,
   durable work state, and authority/effect machinery. Consequence-bound controls may strengthen;
   model-workaround scaffolding must remain removable once its underlying assumption disappears.
7. **Durable execution + reviewable change** — load-bearing objective/authority/checkpoint/recovery
   obligations live outside session memory; mechanically knowable material transitions cannot be
   skipped because an agent forgot them. Cheap supervision detects stalls, repeated failures,
   material scope growth, and stale progress; ambiguous steering uses a replaceable model supervisor.
   Plan the smallest coherent, independently reviewable/landable change units. Before materially
   enlarging scope or changing risk/authority, return to the assigning authority for a decision.
   Trivial work keeps a trivial path.

## Pilot / scale learning contract

Long-term application target: a meaningful real Dish implementation.

- **Pilot-ready**: one bounded real Dish objective can be attempted with bounded effects, durable
  continuity, truthful evidence, stop/recovery, useful trajectory visibility, and reviewable change
  units — without Marco acting as scheduler or forensic monitor.
- **Operationally scalable**: multiple real workstreams raise accepted throughput while Marco's
  scheduling/recovery burden stays flat or falls.

## Non-goals

Zero failures; maximizing agents, tokens, or session length; a permanent recursive agent hierarchy;
messages as authority; a universal heavy workflow; a generalized telemetry/incident platform without
need; permanent LOC thresholds; a scheduler/work-graph/claims/PostgreSQL rewrite merely because it's
plausible; provider-specific authority roots; keeping obsolete safeguards forever; removing Marco
from semantic, product, or risk judgment.

## Success signals

Accepted autonomous throughput rises while Marco's relay/poll/reconcile/rescue burden falls or stays
flat; failures become cheaper to detect, contain, and recover from; change units remain reviewable;
outcome movement remains causally connected to process/tool effort; context, coordination, and cost
per accepted result improves; each stage leaves evidence that can justify or reject the next
mechanism; obsolete scaffolding is removed.
